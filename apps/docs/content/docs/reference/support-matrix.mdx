## Distribution platforms

{/* planr:linux-release-portability:start surface=support schema=1 */}
> **Linux release portability — corrected**
>
> Contract state: `status=corrected`; `affectedThrough=v1.7.2`; `correctedFrom=v1.7.3`.
> Published Linux release, installer, and npm binaries through v1.7.2 require GLIBC_2.39; macOS is unaffected.
> Starting with v1.7.3, current Linux release, installer, and npm artifacts are static-musl executables and do not require glibc.
> On an affected Linux release, build from source on the target distribution or upgrade to v1.7.3.
{/* planr:linux-release-portability:end surface=support schema=1 */}

| Platform | Release/npm binary | Notes |
| --- | --- | --- |
| macOS arm64 | Supported | Homebrew, installer, npm, source |
| macOS x86_64 | Supported | Homebrew, installer, npm, source |
| Linux x86_64 | Supported from v1.7.3 | Static-musl release/npm/installer; older affected release: v1.7.2 |
| Linux arm64 | Supported from v1.7.3 | Static-musl release/npm/installer; older affected release: v1.7.2 |
| Native Windows | Not published | Use WSL 2 or build from source at your own integration boundary |

The v1.7.2 Linux release and npm binaries are dynamically linked GNU executables that require GLIBC_2.39. This is a known compatibility issue; macOS is unaffected. Linux users without GLIBC_2.39 should upgrade to v1.7.3 or newer or build from source on the target distribution.

Release and pull-request CI build static-musl artifacts on native runners, reject dynamic ELF dependencies or glibc symbols, and replay a fresh Planr lifecycle in digest-pinned Alpine 3.20.8 before accepting the exact tarball and npm bytes. The npm wrapper requires Node.js 18+. Native/Homebrew installs do not require Node.js. Building Planr requires Rust 1.85+. Building this documentation site requires Node.js 22+ and the pinned pnpm version.

## Transports and services

- CLI: local process.
- MCP: stdio, newline-delimited JSON-RPC.
- HTTP: localhost-only `127.0.0.1`, default port 7526.
- Events: SSE at `/v1/events/stream`.
- Hosted Planr service: none required.

MCP and HTTP expose overlapping application services but are not identical surface-for-surface. Use runtime discovery and this reference rather than assuming a CLI spelling maps mechanically to a tool or route.
