title: Local HTTP API
description: Complete localhost FeatureRun, ReviewGate, JSON endpoint, SSE, request, and security contract.
---

Start the server with `planr serve --port 7526`. It binds only `127.0.0.1`; there is no remote bind option or authentication layer. Do not expose it through a proxy or tunnel without adding your own access control.

## Stream and health

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/v1/events/stream` | Server-Sent Events; recent replay then live events and heartbeats |
| Any non-OPTIONS method | `/health` | Returns `{ "ok": true }`; use GET for conventional health checks |

## Context, artifacts, events, and search

| Method | Path |
| --- | --- |
| POST | `/v1/contexts` |
| GET, POST | `/v1/artifacts` |
| GET | `/v1/artifacts/{id}` |
| GET | `/v1/events?item={id}&limit={n}` |
| GET | `/v1/debug/bundle?item={id}` |
| GET | `/v1/search?q={query}` |

POST bodies are JSON objects. Invalid JSON returns HTTP 400 with `bad_request`; payloads larger than the server limit return 413. `OPTIONS` returns 204. JSON errors use `{ "error": { "code", "message", "details" } }`. The server sends permissive localhost CORS headers, which is not a substitute for network isolation.

The API calls the same application services as CLI/MCP; state and gate semantics are identical. Use [Outputs and Errors](/docs/reference/outputs-and-errors) for error codes.
