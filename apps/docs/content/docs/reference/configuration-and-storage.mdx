## Runtime environment

| Variable | Meaning |
| --- | --- |
| `PLANR_DB` | Database path when `--db` is absent. Default: discovered workspace `.planr/planr.sqlite`. |
| `PLANR_WORKER_ID` | Preferred stable worker/lease identity. |
| `PLANR_SESSION_ID` | Worker identity fallback when `PLANR_WORKER_ID` is blank or absent. |
| `PLANR_PROFILE` | Observed registry profile fallback for execution logs. |
| `PLANR_MCP_CLIENT` | Narrow child-process client marker. The exact value `grok` is advisory observed-client evidence, not authentication or worker identity. |
| `PI_CODING_AGENT` | Pi sets the exact value `true` for child commands. Planr records that as advisory observed-client evidence, not authentication or worker identity. |
| `PLANR_NATIVE_BIN` | npm wrapper override for a native Planr executable. |

Precedence is explicit CLI flag, then environment, then workspace default where supported. Never reuse one worker ID for concurrent workers.

## Installer environment

`PLANR_BIN`, `PLANR_DOWNLOAD`, `PLANR_REPO`, `PLANR_VERSION`, `PLANR_TARGET`, `PLANR_RELEASE_BASE_URL`, and `PLANR_SKIP_CHECKSUM` configure `scripts/install.sh`. They are installer inputs, not normal CLI runtime configuration. Skipping checksums is only for controlled development mirrors.

## Repository-local paths

| Path | Owner and contents |
| --- | --- |
| `.planr/planr.sqlite` plus `-wal`/`-shm` | Authoritative runtime graph; SQLite WAL mode and 5-second busy timeout |
| `.planr/project/` | Durable project Markdown context pack |
| `.planr/plans/product/<slug>/` | Product plan package and manifest |
| `.planr/plans/build/*.plan.md` | Build plans |
| `.planr/planr.sqlite` ReviewGate tables | Durable review attempts, findings, leases, and final product review state |
| `.planr/artifacts/` | Conventional local verification/package outputs |
| `.planr/agents.toml` | Optional advisory agent profiles and routes |
| `.planr/policy.toml` | Optional provider-neutral usage/execution policy |
| `.planr/integrations/codex-mcp.toml` | Generated project Codex MCP snippet |
| `.mcp.json` | Claude project MCP configuration |
| `.cursor/mcp.json`, `.cursor/agents/`, `.cursor/skills/` | Cursor project integration |
| `.grok/config.toml`, `.grok/agents/`, `.grok/skills/` | Explicit Grok Build project MCP and native workflows; no hooks or plugin tree |
| `.pi/skills/`, `.pi/agents/` | Explicit Pi native Agent Skills and optional pi-subagents roles; no MCP, hooks, settings, or package install |

## npm wrapper binary resolution

The npm wrapper resolves a native binary in this order: `PLANR_NATIVE_BIN`, then `npm/native/<os>-<arch>/planr` from the published package, then `target/release/planr` followed by `target/debug/planr` in a repository checkout. A repository checkout ships no `npm/native/` binaries, so local `npm link` usage falls back to your cargo build.

`planr install ... --dry-run` previews generated client paths. Optional routing lifecycle is external to Planr; Planr only reads repository-local provider-neutral declarations and never edits user-global routing configuration.

[Switchloom](https://switchloom.ai) owns published external routing lifecycle for its [repository](https://github.com/instructa/switchloom), [v0.3.2 release](https://github.com/instructa/switchloom/releases/tag/v0.3.2), [current corrected quickstart](https://github.com/instructa/switchloom#setup-from-the-website), [v0.3.2 tagged quickstart](https://github.com/instructa/switchloom/blob/v0.3.2/README.md#setup-from-the-website), and [v0.3.2 repository lifecycle docs](https://github.com/instructa/switchloom/blob/v0.3.2/docs/preset-composition.md#repository-lifecycle-commands). Follow those external docs for Switchloom lifecycle, use explicit `switchloom@0.3.2` commands for the verified Planr contract, and remember that Planr consumes only the resulting `.planr/agents.toml`, `.planr/policy.toml`, and route evidence. The tagged v0.3.2 README quickstart preserves stale `0.3.1` command examples, so prefer the current corrected quickstart and the pinned operator flow in [Switchloom plugins](/docs/plugins/switchloom).

## Privacy and backup

The database, logs, contexts, artifacts, package exports, and debug bundles can contain internal paths and operational metadata. Planr minimizes review/debug output but cannot classify your content. Inspect and sanitize before sharing. Do not copy a live database between active writers; use [Packages and Reuse](/docs/guides/packages-and-reuse) for explicit transport.
