---
title: Review and Fix Loops
description: Audit evidence independently and keep findings as explicit gated work.
---

## Maker: submit evidence

```bash
export PLANR_WORKER_ID="feature-maker"
planr done <item-id> --summary "Implemented feature" --files src/feature.rs \
  --cmd "cargo test feature" --tests "feature suite passed" --json
```

Planr materiality decides whether this settlement creates or reuses a ReviewGate. For an intentional checkpoint beyond computed materiality, use `--escalate <reason>` together with `--escalation-ref` and `--escalation-explanation`.

## Checker: inspect before deciding

```bash
export PLANR_WORKER_ID="feature-checker"
planr pick --plan <plan-id> --work-type review --json
planr review evidence <target-item-id> --json
planr trace item <target-item-id> --json
```

Compare acceptance criteria, implementation, focused tests, regressions, logs, and relevant live behavior. Review evidence distinguishes files named by item logs from unrelated dirty files.

## Clean verdict

```bash
planr review close <review-gate-id> \
  --verdict complete \
  --reviewer feature-checker \
  --json
```

## Findings verdict

```bash
planr review close <review-gate-id> \
  --verdict not-complete \
  --reviewer feature-checker \
  --findings "Empty input bypasses validation; add a regression test." \
  --json
planr review show <review-gate-id> --json
```

Planr records an immutable attempt and durable findings on the same durable review gate. The FeatureRun remains gated. The responsible maker repairs only the named findings, records new evidence, and explicitly resolves their ids; the same gate then becomes ready for independent re-review. No workflow-only review or fix map items are created.

```bash
export PLANR_WORKER_ID="feature-maker"
planr pick --plan <plan-id> --work-type code --json
```

The pick has `work_packet.kind: "outcome"`, `mode: "finding_repair"`, and the same gate in `execution_state`. It does not have a synthetic fix item. After changing only the named finding scope, attach evidence to the gate's outcome item and resolve the finding:

```bash
planr log add --item <review-gate-scope-item-id> \
  --summary "Fixed empty input validation and added regression coverage." \
  --files src/feature.rs --files tests/feature.rs \
  --cmd "cargo test feature_empty_input -- --exact" \
  --tests "feature_empty_input passed" \
  --json
planr review findings <same-review-gate-id> --resolve <finding-id> --json

export PLANR_WORKER_ID="feature-checker"
planr pick --plan <plan-id> --work-type review --json
planr review close <same-review-gate-id> \
  --verdict complete \
  --reviewer feature-checker \
  --json
```

## Unclear verdict

Use `unclear` when the available evidence cannot support complete or not-complete. Record exactly what evidence is missing; do not disguise uncertainty as success.
