This path delegates installation and project integration to the guide that owns your runtime while keeping every mutation previewable and project-scoped. Choose exactly one integration below, follow its setup, and return here for the shared receipt before asking for product work.

<Callout type="info" title="Start with the right entry">
  After setup, start ordinary Planr requests with `$planr`. For bounded autonomous delivery, use `$planr-goal` first and then the generated `$planr-loop` handoff.
</Callout>

## Verify the setup receipt

Do not accept “installed” as the only result. The agent must report the detected client and repository, resolved Planr binary and version, whether the project already existed, every integration path changed or preserved, plugin/skill status, structured doctor result, any reload or trust action, and the exact next `$planr` prompt.

The setup is complete only when `planr project show --json` reads the project. For Codex, Claude Code, Cursor, or Grok Build, also require `planr doctor --client <client> --json` to report the real client status; generic MCP and CLI-only operators should replay the read-only commands in their integration guide. A missing reload action or a preserved conflict is an honest incomplete step, not permission to overwrite configuration.
