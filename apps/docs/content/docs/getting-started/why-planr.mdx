---
title: Why Planr
description: Understand where Planr helps, what it owns, and what it deliberately leaves to coding agents.
---

Planr coordinates work that must survive chat boundaries, multiple clients, and interrupted execution. It combines readable Markdown plans with a durable local map that owns dependencies, status, leases, reviews, approvals, and completion.

## Use Planr when

- several coding agents or clients need to share one trustworthy state;
- completion must include files, commands, tests, and live verification evidence;
- work can be interrupted and resumed without reconstructing intent from a transcript;
- review findings should become explicit fix and follow-up work instead of disappearing into chat.

## Planr is not

Planr is not a cloud project manager, a hosted agent runtime, or a replacement for your coding client. It coordinates the work while Codex, Claude Code, Cursor, MCP hosts, CLI users, and human reviewers perform it.

## The ownership boundary

Plans explain the desired outcome. The map owns live execution state. Workers hold atomic picks, logs provide durable evidence, and reviews or approvals gate closure where they carry signal.
