---
title: Choose Your Interface
description: Decide how Codex, Claude Code, Cursor, Grok Build, generic MCP hosts, and CLI-only workflows connect to Planr.
---

Every interface operates on the same `.planr` project, plans, map, logs, and reviews. Choose by where you want agents or humans to issue commands—not by a different Planr data model.

| Interface | Best for | Setup |
| --- | --- | --- |
| Codex | Codex skills, MCP tools, project hooks, and role prompts | [Codex integration](/docs/integrations/codex) |
| Claude Code | Claude plugin skills plus project-scoped MCP and hooks | [Claude Code integration](/docs/integrations/claude-code) |
| Cursor | Project MCP, agents, skills, hooks, and optional deeplink | [Cursor integration](/docs/integrations/cursor) |
| Grok Build | Explicitly opted-in native skills, agents, and project MCP; no hooks in v1 | [Grok Build integration](/docs/integrations/grok-build) |
| Generic MCP | Any stdio-capable MCP host | [Generic MCP integration](/docs/integrations/generic-mcp) |
| CLI only | Shell scripts, CI, or operators who want no client files | [CLI-only workflow](/docs/integrations/cli-only) |

<Callout type="info" title="One lifecycle, multiple surfaces">
  Installation and the idea-to-close workflow remain canonical in Getting Started. Integration pages only document the setup and verification differences for each interface.
</Callout>

You can preview first-party client changes before writing files:

```bash
planr install codex --dry-run
planr install claude --dry-run
planr install cursor --dry-run
planr install grok --dry-run
```

After setup, use `planr doctor --client grok` for Grok. The legacy `--client all` selection intentionally remains Codex, Claude Code, and Cursor only, so Grok adoption is never implicit.
